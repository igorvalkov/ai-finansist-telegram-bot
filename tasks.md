## Последнее изменение

Добавлена проектная конфигурация Context7 MCP в `.codex/config.toml`: HTTPS endpoint, allowlist двух справочных инструментов, без ключей в репозитории. В `AGENTS.md` добавлено ограничение не отправлять Context7 секреты, финансовые данные или непубличный код. Проверка через `codex mcp list` не завершилась: CLI в текущей shell-среде не разрешил `CODEX_HOME`; загрузку сервера в Codex runtime нужно подтвердить после доверия папке/перезагрузки. Добавлены repo-local навыки `.agents/skills/finance-bot-tester/` и `.agents/skills/security-review/`; `AGENTS.md` требует применять их к каждому релевантному изменению кода. Создан публичный `igorvalkov/ai-finansist-telegram-bot`, в него загружены файлы проекта; прежний `obucheniye` оставлен без изменений. Проверка навыков валидатором и Python-тесты ожидают рабочей среды Python; локальная Git-история ещё не синхронизирована с новым репозиторием.


Этап баланса и ручного курса: в `database.py` добавлены персональный курс, подсчёт чистого баланса отдельно по валютам через `Decimal` и валидация положительных конечных сумм при сохранении. В `bot.py` добавлены двуязычные кнопочные сценарии просмотра баланса и ввода/отмены курса. Добавлены unit-тесты на нулевой баланс, точность, изоляцию пользователей и ошибочные суммы/курсы. `git diff --check` прошёл; Python unit-тесты не запустились из-за недоступного Windows Store alias, Telegram-интеграция не проверена. Ручной security-review не выявил межпользовательского доступа: все операции используют Telegram ID отправителя, SQL параметризован, финансовые вычисления используют Decimal; динамические проверки недоступны. README обновлён, имя репозитория в плане исправлено.

Этап управления сохранёнными операциями: добавлены постраничный список, просмотр операции, редактирование типа, суммы, валюты, категории, описания и даты, а также подтверждение перед редактированием/удалением. Обработчики и методы БД используют Telegram ID владельца; SQL параметризован, callback-данные проверяются по FSM и ID операции; перед изменением/удалением сравнивается исходная запись, чтобы отвергать устаревшее подтверждение.
